# 波及範圍（claude-dev-system；借鏡 pstack 的 blast-radius）

**觸發（可判定，任一成立）**：diff 動到的符號在專案裡 Grep 到 ≥3 個呼叫處；改了函式簽章、回傳形狀、預設值、共用元件、資料表／JSON 欄位、環境變數或設定鍵。只改文件、測試期望值、或 Grep 只在同一檔命中的私有函式 → 不用做。

1. **列符號**：從 `git diff` 取出改動的函式名、類別名、欄位名、設定鍵、路由。
2. **找呼叫端**：每個符號 Grep 整個專案（排除 node_modules、.venv、build、dist），列表：檔案:行、用法一句、是否已在 diff 內。
3. **分三類**：直接呼叫／間接（介面、事件、排程、CLI 參數、模板）／資料（已寫進檔案、資料庫、快取的舊格式）。間接與資料類最常漏，各至少想過一次並寫「無」或列出。
4. **逐條判定**：對每一條寫「會壞／不會壞」與理由（簽章變了？回傳形狀變了？預設值變了？副作用變了？）。判定不了的另列「待確認」，不可寫成「不會壞」。
5. **實跑一條**：挑最關鍵的（最多人用，或資料類）用真實指令、測試或實際開頁跑一次，把輸出貼進回報；有專案驗證 skill（`cds-verify-app` 生成的）就照它走命中的功能。
6. **回報格式**：「波及 N 處（直接 a／間接 b／資料 c）；已實跑 X 結果 ✅；其餘依程式判定無影響；待確認：…」。有待確認就不可說「安全」。
