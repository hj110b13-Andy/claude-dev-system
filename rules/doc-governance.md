# 文件與規則治理（細則）

- 規則分層見 `README.md`；專案專屬內容（業務規則、資料模型、專屬 API、專案命令）只留在專案。
- 新規則要寫：起因（日期＋使用者原話或事件）、規則本身、可驗證的做法；能具名就具名（便於 grep）。
- 精簡、合併、搬移任何紀錄或規則時：①原話、根因、數字、驗收標準、日期只能移位置不能刪；②改完跑
  `python ~/.claude/claude-dev-system/tools/progress-diff.py --old-file <改前> --new <改後> [--new <封存>]`，逐條確認找不到的句子是「改寫」還是「遺漏」，遺漏的補回；③比對結果寫進 commit 訊息。
- 文件要與實作一致：改動資料流或介面時同步更新架構文件；自動產生的文件（`moduleInventory.py` 產出）不手改。
- 定期瘦身（每週或檔案過長時）：只合併重複、縮短措辭、搬舊日誌；程式瘦身前用 grep／匯入關係確認沒有呼叫端。
