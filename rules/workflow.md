# 通用工作流程（細則）

## 每次任務的生命週期（規格 11.1～11.4）
1. **開始**：先讀專案規則、相關模組、主要介面、測試命令、既有工作狀態（交接紀錄）；全新專案才做初始盤點（`tools/depgraph.py`、`tools/moduleInventory.py`）。
2. **修改前**：寫下目標與驗收條件、受影響模組、相依與資料流、要保留的既有行為、要跑的測試與文件、風險與回復方式。
3. **新增功能**：先用既有擴充點；改核心要說明原因與影響範圍。
4. **完成時**檢查：功能完成？測試通過？影響其他模組？文件要更新？留下待辦？重要決策要記錄？出現新的架構問題？小修不做全專案深度分析，重大架構變更或週期維護才做。

## 排工作流（先排再做）
- 盤點：新需求、上次中斷點、未提交檔、進行中 agent、剩餘待辦。中斷的 agent 優先 SendMessage 接續。
- 依「會動到的檔案」分批，不依需求先後；同檔批次排先後，不同檔批次平行。
- 驗證合併做：同類改動整批改完才驗證一次。
- 先做便宜、能解鎖別人的事；需要使用者決定的一次問完。
- 新需求是累加不是取代：追蹤所有未完成項目直到做完。

## 獨立驗證與卡關升級
- 大改動（新功能、跨多檔、AI 行為、資料正確性）改完派 1 個驗證 agent，限時（建議 30 分鐘、單步 >3 分鐘放棄並記「未能驗證」），只驗這次改動的範圍，通過一句話、問題寫重現步驟／預期／實際。
- 同一類問題連續失敗 2 次：第 3 次同步派 2 個不同模型的 agent 查解法，與自己的嘗試交疊進行。

## 用量收尾（配合 hooks/usage_guard.py）
- 門檻（預設 5 小時 ≥80% 或 7 天 ≥97%，可在 `config/dispatch-config.json` 調整）觸發時：不再派新 agent、不開新待辦；能在上限前做完的讓它做完，做不完的通知 agent 收尾（commit、存 patch、交報告）；更新交接紀錄；推送。
- 7 天門檻觸發要寫「詳細版」交接：每個待辦寫到不看對話也能做（背景、原話、根因、檔案、下一步指令、驗收標準）。
- 開始大任務前先 `python ~/.claude/claude-dev-system/hooks/usage_guard.py --print` 估夠不夠，不夠先告訴使用者選項。

## 背景等待
- 等背景工作時定期主動回報（帶實際進度數字），不整段沉默；agent 交完最終報告就停掉它。
