# 專案驗證 skill 生成器（claude-dev-system；借鏡 pstack 的 create-verification-skill）

產出：`<專案>/.claude/skills/verify-<專案名>/SKILL.md`（專案層，跟著 repo 走）。不適用：純腳本、函式庫、沒有可啟動入口的專案——用單元測試即可。

1. **讀專案**：啟動方式（package.json scripts、pyproject、Makefile、docker-compose、README）、埠號、路由／頁面／API 端點清單、既有測試、專案 CLAUDE.md 列的必測頁面。
2. **寫五段，每段是可直接執行的指令或步驟，不用形容詞**：
   ① 啟動：指令、埠、等幾秒、怎麼知道起來了（看到哪行 log 或哪個網址回 200）。
   ② 健康檢查：開哪個網址，看到什麼文字或狀態碼才算活著。
   ③ 功能走法：每個功能一筆——使用者怎麼到達（網址／點哪裡）、agent 怎麼操作（Claude in Chrome 或 curl）、看到什麼才算對（具體文字或數字）。
   ④ 證據：截哪一頁、記哪個數字；回報寫「看到什麼」，不寫「測試通過」。
   ⑤ 清理：只關自己開的程序，**記下啟動時的 PID、依 PID 關伺服器本體**（只停背景任務會讓 next／vite 本體留著佔埠，下次啟動失敗；Stock-web 2026-11-01 實跑踩到），不整批結束 node／python。
   補充（實跑教訓）：判斷埠有沒有空用 `curl` 實際連一下，不用 netstat（同一個監聽埠有時標監聽中有時標已關閉，會誤判）；地圖裡寫的每個檔案路徑生成時要逐一確認存在。
3. **功能地圖**：每個功能加「相關檔案或路徑」（例：K 線頁 → `app/kline/`、`api/quote.py`）。這一欄是之後挑功能的依據。
4. **生成後立刻照它從頭跑一遍**，跑不過就改到過；跑過才算完成，並在專案 CLAUDE.md 加一行指向它。
5. **之後改動時怎麼用（可判定）**：`git diff --name-only` 命中的檔案對地圖找功能 → 只走命中的功能加 ①②；命中共用程式（設定、共用元件、資料層）或命中 ≥3 個功能 → 全走；使用者說「全部驗一遍」或地圖超過 30 天沒更新 → 全走並更新地圖（對照現在的路由與檔案，補新功能、刪已不存在的）。
6. **不可**用修改地圖來掩蓋功能壞掉：地圖只描述「怎麼驗」，驗不過就是程式的問題。
7. **正式站只做唯讀檢查**：預設對本機 dev server 驗；對正式站只跑讀取類項目，會寫入的（送出表單、AI 問答、建議）走本機或測試帳號。若為了驗證加了「免登入唯讀通道」之類的後門，必須是只讀、帶秘密 token、而且在正式站預設關閉或限制來源；把這個決定寫進 skill 的證據段讓人看得到。
