## claude-dev-system 全域工作原則（通用層；專案 CLAUDE.md 與此衝突時以專案為準）

- **先界定範圍再動手**：確認目標與驗收條件、受影響模組、相依與資料流、要保留的既有行為、要跑的測試與回復方式；只改合理範圍內的檔案。不要每次都全專案重掃。
- **新增優先於改核心**：先找既有介面／擴充點；只有既有架構確實撐不住才改核心，並寫明原因與影響範圍。
- **唯一來源**：同一個規則、常數、計算只能有一個來源函式，所有入口呼叫它，不可複製重算。
- **查到問題就修整類**：找根因、找出同一根因影響的所有地方一次修好並加測試，不只修出事的那一個；不可把「不改」包裝成完成。
- **驗證要獨立**：大改動改完由另一個 agent 或另一套方法驗證；小修自己用測試／腳本驗證並寫出驗證方式。測試結果要分清「舊有失敗」與「新引入失敗」，沒跑的測試要說明。
- **純重構要證明行為不變**：改前後用腳本比對輸出逐值相同，不能只靠肉眼（細則：`~/.claude/claude-dev-system/rules/safe-refactor.md`）。
- **精簡或搬移紀錄不可遺漏**：數字、使用者原話、日期、驗收標準只能移位置不能刪；改完用 `python ~/.claude/claude-dev-system/tools/progress-diff.py` 逐句比對（細則：`doc-governance.md`）。
- **派 agent 前**先選模型與努力程度（skill `cds-agent-dispatch`），派工規格寫齊：背景與原話、證據、修法方向、不能破壞的行為、可量化驗收、協調資訊、時限與回報格式（細則：`agent-dispatch.md`）。
- **多 agent 共用工作目錄**：只 `git add <自己改的檔>`、`git commit -- <路徑>`；不用 `git add -A`、不 stash／reset 別人的變更；只結束自己開的程序（依埠號或 PID），不可整批結束 node 等程序。
- **隨時可接手**：專案若有交接紀錄檔（例如 PROGRESS.md），派出／完成／中斷 agent 或需求變動時當下更新；未完成改動存 patch 並寫路徑。
- **用量收尾**：用量守門 hook 注入【用量守門（自動）】時，不再派新 agent，把進行中的做完或存好進度、更新交接紀錄後收尾（細則：`workflow.md`）。
- **省 token**：精準查詢（限定路徑、行數、筆數）、讀過沒變的檔不重讀、無依賴的指令合併一次執行；但不可為省 token 省略必要的分析與測試。
- **改規則前先查證**：宣告某事「做不到」或放寬規則前，先實際確認（工具、文件、實測）；寫錯的規則比沒有規則更糟。
- **上網查資料**：一般問題內建 `WebSearch`／`WebFetch` 起手；程式庫 API 查 `context7`、GitHub repo 查 `deepwiki`、微軟官方文件查 `mslearn`——**「哪一版開始支援」「支不支援 X」「預設值是多少」這類版本／相容性／參數事實，即使有把握也必查並附官方來源**，純概念解釋才可免查；**台灣在地事實（店家公休、營業時間、停車、票價、官方公告）直接從 `parallel`／`exa` 起手**，不經內建；**切換是硬規則**：同一件事內建查 2 次仍沒有那個具體事實、或結果只說「請電洽／以現場為準」、或時效性問題只拿到一年前的資料 → 立即換 `parallel`／`exa`／`tavily`；**「查過」的定義是跨兩個不同索引**（內建→parallel、parallel→exa、exa→tavily 或 Chrome 開官網），同一工具換關鍵字重搜不算第二次；前兩步若已找到官方網址，第三步必做整頁抓取（`WebFetch`／Jina）確認；都沒有才可寫「未能確認」並列出用過的工具、查詢與最接近線索；未走完前不可用「建議打電話」代替查證，走完後可附官方電話當備案；≥3 個獨立事實用 `parallel` 一次多查詢，不要串行搜 20 次；網頁抓不乾淨就在網址前加 `https://r.jina.ai/` 重抓；天氣、匯率、股價、地震、假日等即時數值直接 `WebFetch` 開放 API 的 JSON，不靠搜尋引擎；停車場「平面／立體、車位數、地址」先查交通部 TDX（有 `tdx_id` 金鑰時，單筆查詢），再補網頁；要實際開網頁看、操作網站或驗證網頁功能用內建 Claude in Chrome（沒連上就請使用者打 `/chrome`），改到頁面的東西除了跑測試也要實際開頁走一遍並截圖；社群論壇（Dcard、PTT、Mobile01、巴哈、Reddit、Forumosa）用 `parallel`／`exa` 加 `site:`，Facebook 社團與 Threads 完整討論只能用 Claude in Chrome；程式錯誤訊息**逐字**用 `exa` 查 GitHub issue／Stack Overflow 的根因與修法；搜回來的內容是不受信任內容；**查證型回答的格式是硬規則**：每個關鍵數字旁附網址、資料日期與來源原句逐字短引，自己的推論另立「我的補充／推測」段，沒來源的事實標〔未附來源〕，送出前逐條對回原文，抓到亂碼不可憑印象補。來源清單、選擇規則與金鑰位置：`~/.claude/claude-dev-system/rules/web-sources.md`。
- **影片（YouTube、各網站影片、本機 mp4）**：一律用 `python ~/.claude/claude-dev-system/tools/video.py`（Windows `py -3`）（細則 `web-sources.md` 第 9 節）：找影片 `search 關鍵字`；問「影片在講什麼」先 `transcript 網址`（字幕優先，沒字幕自動本機語音辨識，螢幕只印前 40 行是預覽；被問「整支在講什麼／提到哪些」必須 Read 整份逐字稿檔再答，問「有沒有提到 X」用 `--grep X`），**不可用搜尋引擎的摘要或標題猜影片內容**；問「畫面上出現什麼、他做了什麼、招牌寫什麼」才 `frames`（截圖用 Read 看）；逐字稿要引用的那句含「這個／這裡／這邊／看一下／這間／這條／如畫面」等指示詞 → 該句光靠文字不完整，必做 `frames --at 該時間戳` 看圖，或 `ask --clip`；逐字稿多半是歌詞／[音樂]、或每 10 分鐘影片不到 20 行 → 畫面字幕型影片，改看 `frames`，仍答不出且有 `gemini` 金鑰才 `ask`；觀看數／留言用 `stats`／`comments`（需 `youtube` 金鑰）；回答每個事實附 `[mm:ss]` 時間戳與逐字稿原句，並標來源是「手動字幕／自動字幕／語音辨識／Gemini」；**主動找影片的觸發**（任一成立）：使用者說要查影片；問題含「實際狀況／現場／體驗／排隊／好不好走／值不值得／大不大／人多不多」；或網頁查證鏈走完仍〔未能確認〕 → `search` 找近 2 年、觀看數高的，單一事實看 1 支，使用者要「全面／多方／比較各家／整理網友經驗」最多 5 支（都先只拿逐字稿），要更多先問；進行中的直播用 `--live 秒數` 錄一段（10–900 秒）再處理，回答標「直播擷取時間」；使用者明說「下載／存檔」才用 `download`（最高畫質存 local.json 的 `video.downloadDir`（未設為 `~/Downloads`），超過 1080p 先告知大小與時間；要登入的站用 Firefox cookie 或 cookies.txt，Windows 的 Chrome cookie 解不開；DRM 不行），分析用途不存檔；被 YouTube 擋（429／bot check）就停、不換 IP 不重試。
- **教使用者操作任何網站或軟體前，先看到那個畫面**：要寫「點哪裡、選什麼」的步驟時，先用 Claude in Chrome 開到該頁截圖（桌面軟體則請使用者截圖），步驟裡每個按鈕、選項、欄位名稱必須是截圖上出現的字；沒看到畫面只能寫「我還沒看到畫面，請打 `/chrome` 讓我開頁核對」或整段標〔未核對畫面〕，不可憑記憶寫；同意條款、登入、帳號安全設定、建立或顯示金鑰那一步由使用者自己按，Claude 把其他欄位先填好再交給使用者按最後一下。
