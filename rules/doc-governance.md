# 文件與規則治理（細則）

- 規則分層見 `README.md`；專案專屬內容（業務規則、資料模型、專屬 API、專案命令）只留在專案。
- 新規則要寫：起因（日期＋使用者原話或事件）、規則本身、可驗證的做法；能具名就具名（便於 grep）。
- 精簡、合併、搬移任何紀錄或規則時：①原話、根因、數字、驗收標準、日期只能移位置不能刪；②改完跑
  `python ~/.claude/claude-dev-system/tools/progress-diff.py --old-file <改前> --new <改後> [--new <封存>]`，逐條確認找不到的句子是「改寫」還是「遺漏」，遺漏的補回；③比對結果寫進 commit 訊息。
- 文件要與實作一致：改動資料流或介面時同步更新架構文件；自動產生的文件（`moduleInventory.py` 產出）不手改。
- 定期瘦身（每週或檔案過長時）：只合併重複、縮短措辭、搬舊日誌；程式瘦身前用 grep／匯入關係確認沒有呼叫端。

# 完整規則原文（自 Stock-web 全域工作流規則去專案化，使用者原話、數字、日期原樣保留）

## 規則十二：定期瘦身，且瘦身前後功能與細節必須一致（2026-10-11 使用者要求）

- **重點不是資料夾大小**（git 內容約 5MB；node_modules、.next、.cache 不同步），而是**每次都會讀的文字**與**沒在用的程式**：①CLAUDE.md（每則訊息都載入）②交接紀錄檔（每次接手都讀）③沒有任何地方用到的程式、腳本、元件、快取 key。
- **觸發**：每週至少一次；或 CLAUDE.md 超過 180 行、交接紀錄檔 超過 600 行時，在收尾或空檔主動做（先依規則九評估用量）。這台的硬碟清理（.next 建置快取、殘留 worktree、過期暫存）可順手做，不影響專案。
- **文字瘦身**：只合併重複、縮短措辭、把舊工作日誌搬 archive；規則、數字、使用者原話、日期、驗收標準一條都不能少。改完照規則二第 8 點用程式逐句比對改前改後，逐條確認是改寫不是遺漏，補回後才 commit，比對結果寫進 commit 訊息。
- **程式瘦身**：刪之前用 grep／匯入關係確認沒有任何呼叫端（含 scripts、cron、測試、文件指名）；刪之後 tsc、eslint、vitest、`npm run build` 全過，跨入口一致性測試必過；會影響輸出的（例如合併函式）照規則十一第 7 點比對改前改後輸出逐值相同，必要時比對線上環境實際回應。瘦身做了什麼、比對方式與結果寫進工作日誌；有疑慮的不刪，列進 交接紀錄 待使用者確認。
